## Other numeric-looking receipt fields / limits

- `spectral_bandwidth_hz` is measured and serialized but has no acceptance predicate in current source; no bandwidth threshold should be inferred.
- `integrated_lufs` is serialized when a finite reading above the `-70 LUFS` floor exists; missing/non-finite/`<= -70` values become `null`. There is **no LUFS acceptance window**. The `-70` condition is a reporting/gating treatment, not a loudness target or evidence of silence. `rms_dbfs` is separately reported.
- `thresholds` omits several enforced predicates (channels, codec, bit width, section sample-count exactness, and some condition scoping), so it is not alone a complete executable specification. Receipt `rms_min_exclusive` conflicts with code at exact equality.
- Invalid-probe records use `expected_failure`, `observed_failure`, and status (`expected_failure` / `expected_pass`); they do not use the normal receipt's `measurements`/`sections` schema. Round-22 verifier documents new JSON keys and strict external-consumer compatibility as untested.
- Not measured here: current 13-file distributions, nearest margins, all thresholds’ boundary behavior, isolated control coverage for each gate, and any empirical/audible validity. Round-22 non-author replay supports its named outcomes, not every possible input or edge case.
