# Round 17 critic — challenge to 200 Hz coverage claim

## Scope and method

Read `.shokunin/audio/LOG.md`, the current `.shokunin/audio/corpus/fixtures/measure_audio.py`, `.shokunin/audio/corpus/fixtures/build_artifacts.py`, and the available `r17-reviewer.md`. This is a source/math critique, not candidate or runner verification. I did not run shell commands; exact shell command/exits: **none**. I did a local Python calculation of the proposed `.015 → .050` 200 Hz sine recipe after PCM16 quantization. This does not substitute for `measure_audio.py` or independent evidence.

## Challenges

1. **Coverage novelty is narrow, not self-evident.** The baseline already contains 120 Hz and 180 Hz stepped layers; both use the same 4 s, two-section format and same section contrast / seam gates. The proposed 200 Hz fixture extends the tested component-frequency set by 20 Hz, but it does not add a new gate class, waveform structure, section order, or failure mechanism. All three frequencies remain inside the same 100–2000 Hz generic centroid band, which is not a frequency-specific coverage demonstration. The declared move can be described as one additional original fixture / tested frequency point only if the final canonical inventory and independent run establish it; do not imply broad frequency coverage or improved detection. The 200 Hz choice is a new design constant, not evidence it is representative or perceptually meaningful.

2. **The nominal recipe has little slope headroom.** For the declared two-sine-only recipe at 48 kHz with the boundary at t=2s, 200 Hz is exactly at a phase zero at the section boundary. I calculated after rounding/clipping to PCM16 (then normalizing by 32767): internal adjacent-sample gap ≈ `0.0003967406` FS, internal side-slope mismatch ≈ `0.0009155553` FS/sample, and outer side-slope mismatch ≈ `0.0009155553` FS/sample. Both slope values are below `.001`, but only by about `0.00008445` FS/sample (~8.4% of the limit). The internal gap has much more margin to `.03`; the outer endpoint gap is ≈ `.00131230` FS. These are arithmetic predictions for the stated recipe, not decoded runner receipts. This is not a robust margin claim: coefficient rounding, changing boundary phase, adding a bed/harmonic, or even a small sample edit can consume the slope headroom. Report exact measured margin and keep internal and outer slope checks distinct; passing the shared numeric bound does not demonstrate a perceptually smooth join.

3. **“Distinct third layer” is ambiguous unless defined operationally.** The runner's existing distinctness rule compares only names ending `_alt` against the unsuffixed baseline, using duration or relative centroid difference. `stem_layer_third` is not in that comparison, and its 4 s duration matches both layers. Thus adding it neither passes nor fails an existing automated distinctness comparison. A different component frequency and a distinct SHA would establish different data, not perceptual distinctness or meaningful content diversity. Avoid saying the current variant-comparison rule proves the third fixture distinct; separately report exact canonical hash and frequency-specific component measurement. If distinctness is meant to cover it, that requires an explicit spec change and must not be smuggled in as a pass.

4. **The numeric gates are proxies, not audibility evidence.** `section_contrast` measures the magnitude of one FFT bin at the chosen frequency per 2 s half, rejects amplitudes below `.01`, then checks a signed amplitude ratio against 6 dB. It does not assess tonal prominence, masking, temporal perception, smoothness, music quality, or listener discrimination. Its “valid” amplitudes only mean the numeric floor was met. Likewise, endpoint/sample-slope and centroid thresholds are deterministic fixture checks, not audibility or engine behavior. The full-waveform centroid is broad and does not independently validate the 200 Hz component. No listening, blinded comparison, or perceptual calibration is in scope or supplied.

## Disposition / evidence needed

Treat this as an unverified, narrow fixture-frequency coverage proposal. Do not count the recipe prediction or reviewer recommendation as a fit/pass. Before any coverage verdict, require the actual generated WAV's format, duration, decoded peak/RMS, centroid, outer endpoint and slope, section-bin amplitudes/validity/contrast, internal gap and side-slope, exact SHA, plus independent 13-fixture/mode replay showing all twelve old canonical hashes and old failure behavior unchanged. Keep limits stated as synthetic numeric harness evidence only. No threshold relaxation or audibility, engine, or production claim is supported.
