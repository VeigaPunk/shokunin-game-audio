# Round 6 scout — pre-receipt exception map

Scope: static read of the pre-integration `.shokunin/audio/corpus/fixtures/measure_audio.py` as assigned. No commands were run, no malformed inputs were exercised, and no source or artifacts were changed. This maps plausible failure paths, not observed exception outcomes. The current script has no `--probe-invalid` option yet.

## Control flow and operations before the JSON receipt

1. `argparse` parses the three existing probe flags and calls `parser.error()` if more than one is selected. This exits with argparse's error status before any receipt.
2. `command(sys.executable, build_artifacts.py, ...)` uses `subprocess.run(..., check=True, capture_output=True)`. A missing executable/script, builder error, or nonzero builder exit raises `FileNotFoundError`/`OSError`/`CalledProcessError`; no receipt is written. It does not capture or convert these errors into a measurement failure.
3. The dict comprehension calls `measure()` on all ten canonical artifacts. Each call has multiple unguarded external and data-dependent steps:
   - `ffprobe` invocation can fail (including missing executable or nonzero exit); `json.loads` can reject malformed output; `probe["streams"][0]`, `probe["format"]["duration"]`, or stream keys can raise `KeyError`/`IndexError`; `int(...)` / `float(...)` can raise `ValueError`/`TypeError`.
   - `sox` invocation can fail. `np.frombuffer(..., dtype="<f4")` raises `ValueError` if byte length is not a multiple of four. Empty/degenerate sample arrays can make FFT/statistic operations fail or produce non-finite values; there is no sample-count, finite-sample, or decode-shape validation before centroid, bandwidth, RMS and peak computations. Some degenerate cases produce NumPy warnings/NaN rather than an exception, but later `json.dumps(..., allow_nan=False)` can then fail.
   - `ffmpeg` invocation can fail. Its stderr `.decode()` can raise `UnicodeDecodeError`. Missing or unparseable loudness text alone is handled as `lufs=None`; a matching numeric token is converted with `float`.
   - Seam calculations index `samples[0]`, `samples[-1]`, `samples[-2]`, and `samples[1]` for loop specs. Empty or one-sample decoded loop data can raise `IndexError`; there is no guard before indexing.
   - `path.relative_to(ROOT)` can raise `ValueError` if a supplied path is outside the expected root.
4. Probe-specific measurement runs after the ten clean measurements. A missing/bad slope or flat probe fails through the same `measure()` paths above. These failures happen before output creation.
5. `section_contrast()` runs on `stem_sections` (and `flat30_probe` in flat mode). It decodes via SoX and uses `np.split(samples, 2)` before checking the exact expected sample count. Odd sample counts can raise `ValueError`; even but short inputs can produce an FFT with fewer than 61 bins and `np.fft.rfft(half)[60]` can raise `IndexError`. Empty halves may produce NaNs/warnings. The later `valid` predicate checks `len(samples) == 192000`, finite amplitudes, and floors, but only after splitting, FFT indexing and RMS calculations, so it cannot protect those earlier operations.
6. Distinctness computes `... / base["spectral_centroid_hz"]` without a zero/finite guard. Current declared bands make a zero baseline unexpected for canonical fixtures, but it is not handled if encountered.
7. Receipt assembly and persistence are also unguarded: timestamp/path construction and `out.mkdir(parents=True)` can fail (for example permission or collision); JSON serialization with `allow_nan=False` raises `ValueError` for non-finite values; `write_text` can fail on filesystem errors. The receipt is written only after every prior stage succeeds.

The expected checks (format, duration, level, spectrum, seam, distinctness and section contrast) append strings to `failures` and still reach a JSON receipt. They are not exception handlers for subprocess, decode, shape, indexing, or filesystem failures. Thus the pre-round-6 implementation supports ordinary measured threshold failures, but does not establish structured receipts for malformed/truncated inputs. No inference about all malformed WAVs, codec security, or the post-integration implementation is made here.
