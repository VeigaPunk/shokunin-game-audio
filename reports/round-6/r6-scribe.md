# Round 6 scribe: invalid-control decision table proposal

Scope: draft for the three declared invalid controls only. This is an expected-outcome proposal, not execution evidence; no command was run and no WAV was created here. The integrated probe mode and receipt schema are not yet implemented, so proposed labels below must be mapped to the parent's concrete schema without claiming a pass.

| Control | Input condition | Expected structured result | Expected failure type | Caveat / what it does not show |
|---|---|---|---|---|
| `short_sections.wav` | Valid PCM16 mono WAV, deliberately shorter than the 192,000 decoded samples required by the 4 s `stem_sections` check; should otherwise be decodable. | One per-probe JSON result with a non-empty failure list; classify as `section count` (or a clearly equivalent explicit invalid-length category). Exit 1 for the invalid-probe run; no traceback and no missing receipt. | `section count` | Validate sample count before splitting or indexing the 30 Hz FFT bin. The current `section_contrast()` splits/indexes before checking exact count; depending on the chosen short length it can either throw or compute misleading values. A short but even input may not throw, so “no exception” alone is not success. This only covers the chosen length/path, not every truncation. |
| `corrupt.wav` | Deliberately malformed/corrupt header or bytes that make the declared WAV undecodable. | One per-probe JSON result with a non-empty failure list and explicit `decode` (or equivalent corrupt-input) classification; exit 1, receipt retained, no traceback. | `decode` | Current `ffprobe`/`sox` calls use `check=True`; they raise `CalledProcessError` on nonzero exit. Catch only expected external probe/decode failures at this boundary and retain useful bounded diagnostics. Do not turn arbitrary programming errors into “decode” failures. One corrupt fixture does not establish parser security, exhaustive malformed-file handling, or safe resource limits. |
| `wrong_format.wav` | Decodable PCM WAV with a rate other than 48 kHz and/or two channels, generated explicitly and recorded in its recipe. | One per-probe JSON result with a non-empty failure list naming the observed rate/channel and expected 48 kHz mono; exit 1, receipt retained, no traceback. | `format` | `ffprobe` should succeed; classify from inspected metadata before applying rate-sensitive section/FFT assumptions. A wrong-rate file can shift the meaning of the fixed 30 Hz FFT bin, and stereo decoding changes sample count/layout assumptions. Avoid treating a later derived-metric error as proof that the format check worked. This tests only the chosen rate/channel combination, not all formats. |

## Decision rule and boundaries

Count a control as behaving as intended only if its own receipt entry identifies the expected failure type, the overall command exits nonzero, a JSON receipt is written, and no uncaught traceback appears. Prefer per-probe outcomes so one bad file cannot mask another; do not infer isolation unless receipts show it. For the short control, explicit sample-count validation must precede section FFT work. For wrong-format input, metadata validation must precede any rate-dependent section analysis. For corrupt input, report the expected tool failure without swallowing unrelated exceptions.

These are narrow malformed/truncated-input reporting checks. They do not establish behavior for every malformed WAV, robustness/security against hostile media, codec behavior, or production suitability. Clean-fixture preservation, old-control behavior, unchanged hashes, and independent replay remain separate required evidence; this draft verifies none of them.
