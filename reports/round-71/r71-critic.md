## Findings by severity

### F1 — MEDIUM (latent, live-demonstrated): `_tail` does not strip ` @ 0x<addr>` module tags — real forks record as unstable N-way phantom partitions

`ffprobe_leg._tail` (measure_audio.py:645–650, added in the D2 correction)
normalizes backtick names and the literal `probe_arg`, but unlike the sibling
SoX arm's normalizer (`transport_leg`, measure_audio.py:279–280) it does NOT
strip ffmpeg's `[mod @ 0x<aslr-addr>]` context tags. Any member whose ffmpeg
decode emits a module-tagged last stderr line produces a `ffmpeg_error` that
is (a) non-replayable byte-wise and (b) unique per arm — so the true fork
shape is inflated into singleton groups.

Counterexample member (constructed in scratch): `corpus/live/r71-critic/test.wv`
— a valid wavpack file (`ffmpeg -f lavfi -i sine -c:a wavpack`). It is a
*legitimate* r71-class member whose real verdict fork is
`{file} | {stdin_pipe, redirected_fd, fifo_path}` (file arm decodes clean —
1 lseek on the input fd; all nonseekable transports emit
`Error during demuxing`). Driven through the landed fixture twice:

```
$ python3 corpus/live/r71-critic/matrix_probe.py   # calls ffprobe_transport_entry
run1: 4 groups — stdin_pipe=[in#0/wv @ 0x55f6690368c0] …, redirected_fd=@0x55de6d7698c0, fifo_path=@0x559e15e678c0
run2: 4 groups — stdin_pipe=[in#0/wv @ 0x560ef493c8c0] …, redirected_fd=@0x555c88afb8c0, fifo_path=@0x55ebc729e8c0
```

Truth is 2 groups; the receipt records 4, with different bytes each run —
the new ledger family is still not replay-stable on exactly the member class
(decode-partial-failure) the matrix exists to catch. The committed 9-member
receipt is unaffected (verified identical verdict groups across two runs —
`140155796326Z` vs `142028085688Z`); the signature function is what's broken.

Smallest safe correction: in `_tail`, apply the same
`re.sub(r" @ 0x[0-9a-f]+\]", "]", t)` that `transport_leg` already applies
(measure_audio.py:279). One line, keeps both legs' tail classes aligned.

### F3 — LOW (claim precision): "content-probing confirmed" is right but the accept-half is vacuous on this set

Content-probing is genuinely exercised, not masked: all 7 no-match rejects are
post-probe `Invalid data found when processing input` (AVERROR_INVALIDDATA —
pre-probe failures would be I/O/protocol errors), and `dec_act→wav` /
`dec_hcom→hcom` are accepted by content on all 4 transports (probe_score
99/100). The reject-half of the claim is confirmed where it matters:
`extsuffix_f32` and `extsuffix_snd` are SoX *accepts* (exit 0, 128/504
samples, `sndr` detection on `.snd`) that ffmpeg rejects by content on every
transport.

But the claim's other direction — "accepts members SoX extension-rejects when
content is parseable" — has **no member**: nothing in the set is both
ffmpeg-parseable and SoX-extension-rejected. Probes
(`corpus/live/r71-critic/{misnamed.bin,test_asbin.bin,caf_asbin.bin,test_astxw.txw}`):
SoX content-detects wav/mp3/flac/aac/caf even under `.bin`/`.txw` names — its
CHECK table is magic-first, so constructing an extension-reject-but-parseable
member needs a format outside SoX's magic set. Also, "ffmpeg ignores the
name" is measured-true for these members but mechanism-nuanced: extension IS
an `av_probe_input_format3` input — a WAVE-corrupted member
(`r71-critic/corrupt.wav` vs identical `corrupt.bin`) rejects identically,
i.e. extension match alone stays below the accept threshold on this build.
Suggested wording: "no suffix influence measured on this set; both verdict
directions are content-decided."

### F4 — answered affirmatively (receipt annotation owed): redirected_fd ≡ stdin_pipe is mechanical, and the matrix measures 3 realizable ffmpeg transport classes

The fresh-fd-per-subprocess fix is correct (measure_audio.py:591 — `open()`
inside `run()`, closed in `finally`). The equivalence claim is stronger than
the report states — verified at three levels:

- syscall: `strace -f -yy` shows `pipe:` dup()s fd 0 and then performs ONLY
  `fcntl` + `read` + `close` on it — zero `lseek`, zero seekability probe —
  for wav/mp3/tta/m4a/wv/aac/caf inputs, seekable backing fd or real pipe.
- semantic: a CBR mp3 without Xing (`r71-critic/noxing.mp3`) reports
  `duration` on the `file` arm (size-derived, needs seekable input) and omits
  it identically on BOTH `stdin_pipe` and `redirected_fd` — `pipe:` masks the
  fd's seekability entirely.
- fork-boundary: `test.wv` decodes clean on `file`, fails identically on
  `stdin_pipe`, `redirected_fd`, and `fifo_path` — the anonymous-seekable
  quadrant cannot be expressed via `pipe:` on n9.0.1, so the two anonymous
  arms are one transport class.

So under ffmpeg the 4-arm matrix measures 3 distinct realizable classes:
`{file}` (named+seekable), `{fifo_path}` (named+nonseekable),
`{stdin_pipe, redirected_fd}` (anonymous — seekability unrealizable). The arm
metadata still labels `redirected_fd` `seekable: true` (fixture truth the
decoder cannot observe) and the receipt does not record the class collapse —
the knowledge file does (`corpus/knowledge/2026-10-14-ffmpeg-cross-decoder-transport.md`
:16–17). One-line receipt annotation would close it; informational.

### F6 — pass with pathology notes: per-process fifo writers

Fix verified: each `run()` call mkfifos its own fifo on the shared path,
spawns its own `fifo_feed` writer, joins `hold+5`, reaps, unlinks;
`/tmp/transport-r71-*` dirs self-clean (zero leftovers observed post-run; the
one seen mid-flight was a live leg). `reap_fifo_orphans`'s
cmdline-needle covers ffprobe/ffmpeg argv paths; ffmpeg spawns no
grandchildren, so the sweep is a correct belt over `subprocess.run`'s
timeout-kill. Residuals, both unreachable as invoked: a writer thread can
park in `fifo.open("wb")` forever if the subprocess dies before opening
(daemon, dies at exit); `writer.join(timeout=hold+5)` lacks the chunked-feed
span term the SoX legs add (r71 uses oneshot only). Also inherited-stdin on
`file`/`fifo` legs (ffmpeg stdin 'q' polling) — demonstrated unreachable at
this member scale (decode outruns the stdin poll; `printf q | ffmpeg …`
completed identically), same exposure as the status-quo SoX arm.
