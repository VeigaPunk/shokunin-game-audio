# Round 15 critic — 180 Hz layer slope-only claim

## Scope and method

I read the Round 15 declaration in `.shokunin/audio/LOG.md`, current `corpus/fixtures/measure_audio.py` and `build_artifacts.py`, and the original `corpus/artifacts/stem_layer_alt.wav`. I did not run shell commands, edit source, create a candidate or listen to audio. Thus this is an independent source/data critique, **not** a measured sole-failure result or integration review. I wrote no scratch PCM. Existing implementation has no `--probe-layer-alt-slope`; the declared mode is prospective, and parent integration plus a non-author replay are still required.

The source computes the 180 Hz section gate from FFT-bin magnitudes at the two 96,000-frame halves (requires each component amplitude >= .01 FS, each RMS >= .001 FS and second/first ratio >= 6 dB), then the exact midpoint adjacent gap and first-difference mismatch. For the applicable names it fails on strict `gap > .03` or strict `slope mismatch > .001 FS/sample`. The generic fixture measure additionally includes level/format/duration/centroid checks; sole failure can only be established from the exact candidate's runner failure list. Current builder writes the 180 Hz canonical as PCM16 with `np.round(clip(x,-1,1)*32767)`; decoding/quantization must be included in all evidence.

## Falsification checks and cautions

- **Candidate direction matters.** Canonical decoded samples 95998..96001 are `[-23,-12,0,39]` PCM counts (`[-.00070193,-.00036622,0,.00119022]` FS using divisor 32767). The center gap is 12 counts (`.0003662221` FS); the side-slope mismatch is 28 counts (`.000854518` FS/sample), below `.001`. If only frame 96001 is incremented by 13 counts, mismatch becomes 41 counts (`.00125126`), so slope would fail—but changing by **minus** 13 counts gives 15 counts (`.00045778`), which continues to pass. This illustrates polarity/sign dependence; “perturb a frame” alone does not imply the intended failure. These calculations are from source WAV integer samples and do not establish any candidate's full runner outcomes.
- **Slope is a signed second difference before absolute value.** At the midpoint, `abs((x[96001]-x[96000])-(x[95999]-x[95998]))` can be raised by moving the right-side sample in one direction and lowered in the other. A correctly targeted positive edit would nominally need at least six counts from this PCM baseline to exceed 32.767 counts, but exact quantization and the strict comparison govern. A report must show resulting decoded values and margins, not only the requested float increment.
- **The gap check is independent only in the narrow arithmetic sense.** It compares `x[96000]` to `x[95999]`; changing `x[96001]` leaves that pair unchanged. However gap and slope share the same samples, and passing gap does not show either neighboring first difference is small. The existing `.03` gap bound is much looser than the values here, so “slope-only” means only one named numeric runner branch failed on this fixture.
- **Polarity / quantization:** PCM16 is signed and rounded to integer counts before WAV storage; write/read and decoder scaling must not be silently mixed (`/32767` versus decoder float conventions). A sign mistake can reverse whether second difference rises or cancels. One-count increments are about `3.05e-5` FS/sample; report integer samples as well as decoded runner metrics. Clipping is irrelevant only if demonstrated from exact artifact. Do not claim robustness near the threshold based on unquantized intended values.
- **Contrast and centroid do not validate the local edit.** FFT amplitude at 180 Hz and its >=6 dB half ratio, plus generic whole-file centroid/band checks, are broad proxies. A one-sample adjustment can change local metrics while their aggregate checks stay valid, or shift centroid outside its band. Verify both half-bin amplitudes/validity, both RMS values, centroid, generic failures, and every section failure on the exact candidate. A failed contrast/centroid fit is not a sole slope failure. Full sample count/frame rate also matters because index 96000 is the midpoint only for the expected 192000-frame 48 kHz fixture.
- **Audibility is untested.** A discrete slope mismatch exceeding this harness threshold establishes only a synthetic PCM measurement crossing its locally declared number. It establishes no audible click, perceptual salience, musical quality, engine behavior, external compatibility, security, or production readiness.

## Falsification conditions / acceptance evidence needed

Reject a sole-slope claim if runner-decoded side-slope mismatch is not strictly above `.001`, gap is above `.03`, component contrast/validity fails, centroid or any generic check fails, sample count/rate differs, or the failure list contains anything except the existing side-slope branch. Confirm the candidate is built from the original 180 Hz layer, record its SHA-256 and exact generation recipe, decoded samples 95998..96001, and exact shell command/exit/receipt. A separate non-author runner replay should show normal/new-slope/prior controls and canonical hashes unchanged before integration is claimed. Do not infer the verdict from this critique's illustrative 13-count arithmetic.

No new threshold is warranted or proposed. No audible, engine, security, production, or external-reader claim is made.
